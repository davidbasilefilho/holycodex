description: Use when visual changes need rendered judgment; let Root inspect the current result and assign concrete repairs.
---

Root only, for visual tasks. Orchestrate implementation, inspect its rendered
result, judge the visual output, dispatch targeted changes to specialists, and
repeat until the result is excellent and meets the user's requirements.

Follow the visual-inspection order generated for Root's selected capabilities.
Unselected capabilities are not fallbacks. Honor higher-priority active-surface
tool rules. Use the shared development server when needed. Inspect relevant viewports and
states against the user's requirements and repository design system. Report
the specific blocker if no available method supports the required judgment.

Reuse unaffected evidence. Do not run this loop for logic-only changes.
Specialists own implementation and delegated interaction checks.
