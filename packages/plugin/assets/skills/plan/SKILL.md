---
name: plan
description: Use when Root faces unresolved architecture, scope, coordination, or material risk before work begins; produce the implementation-ready decision record.
---

Owner: Root. Boundary: identify alternatives, constraints, risks, route,
acceptance evidence, exclusions, and recovery, then persist the semantic Plan
through `holycodex-agent plan revise`. Specialists may supply facts but may not
decide the outcome.

Root orchestration is mandatory: every task, including trivial work, must be
represented by a delegated Assignment and executed by the appropriate native
specialist. The only direct Root execution exceptions are Git/VCS and
Computer Use when the capability was selected at install. Root retains intent,
acceptance, material decisions, lifecycle, integration, approvals, and final
completion; do not perform implementation locally.

Create or read the current Intent with `holycodex-agent intent ...`, and create
the bounded plan/review assignments before dispatch. A plan is optional for
trivial work, but delegation is not. Do not edit TOON files manually.

Use `request_user_input` before seeking plan approval and whenever ambiguity or
missing material input blocks safe progress; persist that condition as
`needs_root_input` on the Intent or Plan. Apply the repository surgical-
mutation rule: minimize edit/write surface and operation count while remaining
careful, complete, and evidence-driven.

Persist the plan operation as a compact `completed`, `blocked`,
`needs_root_input`, or `failed` result with proof and remaining risk.

Completion: Root has an implementation-ready plan naming scope, owners and
seams, data and control flow, policy, recovery, tests, compatibility, the
preferred shape, and a bounded proof route.
