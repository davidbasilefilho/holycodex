# Existing-host event boundary

Pinned Codex rust-v0.160.1 (`d27764b82f7118f674371e6d6e76271d9d606edb`) already implements experimental `mcpServer/event/stream/start`, `stop` and `notification`. Its start parameters are `threadId`, `server`, `subscriptionId`, provider `name`, `arguments`, and optional `_meta`. Only server `codex_apps` is supported and the connection must already subscribe to the thread. The host forwards `notifications/events/active`, provider notifications and `notifications/events/terminated`; upstream owns bounded reconnect and disconnect cleanup. No extra transport or scheduler is needed.

Source: [request processor](https://github.com/openai/codex/blob/d27764b82f7118f674371e6d6e76271d9d606edb/codex-rs/app-server/src/request_processors/mcp_event_stream.rs), [protocol envelope](https://github.com/openai/codex/blob/d27764b82f7118f674371e6d6e76271d9d606edb/codex-rs/app-server-protocol/src/protocol/v2/mcp.rs).

The connected tool catalog inspected for this implementation exposes GitHub reads/writes but no discoverable GitHub Plugin Runtime `events/stream` event name/schema. This is an accessibility gap, not proof GitHub never supports events. No live subscription was opened. A hosted-automation webhook contract is a different interface and is insufficient evidence for this transport. No guessed event API, private endpoint, new credential or persistent grant is used.

`holycodex_policy::ci_watch` is a tested host-side adapter/reconciliation boundary: it prepares the upstream start envelope only after the caller supplies verified capability prerequisites and a provider-discovered contract. It forwards provider arguments unchanged and interprets no provider payload. Hosts may normalize authoritative reads into its snapshot/gate types; unknown requirements/review coverage cannot report success. Generation tokens reject a read overtaken by a push/wake-up, overlapping read or reconnection; a head re-read rejects incoherent snapshots. Every event is just a request to reconcile. Hosts capture connection_epoch for callbacks; disconnect/termination advances that epoch, so late activation from an old connection cannot mark the new connection active. Missing/terminated/error state falls back to host-owned polling.

This module is not wired to a live GitHub event source or a background runtime worker. The embedded skill is the active behavior change; the typed library boundary is available for an existing host integration once that host verifies the provider contract. No end-to-end watcher, automatic wake-up or polling reduction is claimed. Required-check names/attempts, paginated reads, current review relevance and PR scope remain responsibilities of that host's authorized provider adapter. Existing connected-tool fallback works without any new protocol contract.
